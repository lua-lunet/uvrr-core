The latency literature contains two shorter client paths than the one taken here, and both buy their round trips with infrastructure this design deliberately does not require. NOPaxos orders requests in the network itself: a sequencer stamps a global sequence onto packets in flight, so replicas process a common order and ordinary operations complete in about one client round trip~\cite{nopaxos}. The evaluated fast path uses programmable switching hardware or an SDN control plane; the ordering point is distinguished infrastructure. CURP lets a client complete in one round trip by writing concurrently to the master, which orders and executes, and to witnesses, which retain the request unordered~\cite{curp}. The fast path is sound only while every outstanding operation whose order might be lost is mutually commutative; on a conflict the protocol returns to an ordered replication sync, and the client must reach the master and the witnesses directly rather than any member of the cluster. CORFU shows that a global sequencer need not be custom hardware: its token sequencer is user-space software, with sequencer identity carried in the replicated projection and replaced through reconfiguration~\cite{corfu}. Its clients still obtain a log position and then write to it, two causally dependent stages.
